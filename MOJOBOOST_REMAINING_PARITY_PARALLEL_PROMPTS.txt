After completing the task's primary implementation, do not stop at an isolated module or design. Perform a final safe-integration pass to the maximum extent possible inside your exclusive ownership.

During that final pass:

- Re-read the live production and public call paths relevant to your lane.
- Fuse overlapping implementations inside your owned files into one authoritative implementation.
- Connect the authoritative implementation to every real caller located inside your ownership.
- Ensure existing parameters and state actually flow into it and its results affect real behavior.
- Connect capability checks, explicit unsupported errors, fallback behavior, resource ownership, and cleanup.
- Connect model state to serialization requirements or keep the feature disabled if correct persistence is impossible.
- Connect native behavior to an existing binding seam when that seam is inside your ownership.
- Connect Python APIs only as thin wrappers around native Mojo behavior.
- Update owned documentation and handoffs so they describe actual reachability rather than merely code existence.
- Remove obsolete duplicate glue inside your ownership only when no live caller requires it. Otherwise quarantine and document it.
- Preserve conservative defaults and established fallback paths for every unvalidated implementation.
- Do not cross ownership boundaries, overwrite concurrent work, or make speculative central edits.
- Do not run or write tests, execute programs, build artifacts, run benchmarks, or perform hardware validation.

If complete integration requires files outside your ownership, add an exact READY-TO-APPLY INTEGRATION PATCH section to your handoff. For every required patch specify:

1. Target file and symbol.
2. Required import or export.
3. Exact function or type signature.
4. Call location and control flow.
5. Parameters and state passed in.
6. Return values and errors handled.
7. Lifetime and resource ownership.
8. Fallback and default behavior.
9. Serialization and model-format effect.
10. Public API and documentation effect.
11. Conflict or dependency on another lane.
12. Minimal later focused validation command marked UNRUN.

The task is not considered handed off until it has integrated everything safely possible within its lane and made every remaining cross-lane connection mechanically actionable. Do not claim the capability is supported, validated, performant, or release-ready merely because this integration pass is complete.
