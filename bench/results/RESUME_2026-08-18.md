## The one result that reframes everything else

**The host is never computing. It is blocked on a full command queue.**

The host-step profile (built by a lane today, run by me, `phase_profile.mojo`)
on the leaf-wise arm, 463,715 x 90, 100 trees:

    device_wait   0 calls, 0 ns
    readback      13.36 pct
    encode        85.74 pct, max_ns 25.8 ms against a 0.13 ms mean, 192x
    step curve    41.6 27.7 32.4 20.9 23.7 27.6 | 83.2 77.3 70.4 72.7 73.3

Six cheap steps while the queue fills, then a plateau. That is backpressure
inside the enqueue call, charged to the encode column. So `par_eff 0.91` on
the leaf-wise arm NEVER meant host-bound, and **no host-side optimization can
move any arm's wall clock.** This explains the launch-fusion null (1.004x
after removing 21.5 pct of launches: you cannot remove a wait by removing
launches) and generalizes E15 from the symmetric arm to all of them.

Before opening any lane, ask what resource is scarce. Twice today I argued
from a correct estimate of how much WORK a thing did without checking whether
the resource it used was the constrained one. Both times the estimate was
roughly right and the conclusion was wrong.

## What is queued and unmeasured

- The binning tie-repair fix (`MOJOTREES_BINNING_SORTED_TIE_REPAIR`, default
  off) is BUILT and NOT MEASURED. Its control: on synthetic uniform data it
  must move the number by exactly zero. Known before measuring: covertype has
  tied boundaries on 54 of 54 columns and 13,638 of them against MSD's 176,
  but zero-straddling is 1 of 54 against MSD's 77 of 90, and the fix works by
  noticing a sort that only straddling causes. So it likely helps the dataset
  with the FEWEST ties and does nothing for the one with the most.

**Why this matters more than it sounds.** Commit 29dfaba states, in the
README, that no NVIDIA number and no AMD number exists, not one, and labels
the "a bandwidth-hungry kernel would go faster on a card with its own
high-bandwidth memory" argument a PREDICTION with what would settle it. One
run on that pod settles it. It would also be the first evidence for or
against the portability claim, which today rests on one M4.

Two cautions the reporting session raised and I would carry into any record:

- The driver clears Mojo's floor of exactly 580 by a hair, so the version
  belongs in the record explicitly rather than as "recent enough".
- The 5090 is Blackwell sm_120, which is Modular's "known compatible" tier
  rather than "continuously tested" (B200 is the only NVIDIA part in the
  latter). So a failure there is more likely to be upstream than ours, and a
  result should not be read as a verdict on this repository until that is
  separated.
