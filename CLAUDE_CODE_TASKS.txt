Each task below is self-contained. Copy and send only one task at a time.
Do not run tasks concurrently because several touch the same central types,
serialization format, bindings, and training loops.

=========================================

Work in the `mojoboost` repository. Inspect the current implementation and
git status before editing because the project is evolving quickly. Preserve
unrelated work and do not rewrite existing APIs unnecessarily. Follow the
existing CPU/GPU backend boundary. Add focused equivalence and validation

bindings when public parameters change, run the complete Mojo and Python
suites, run `git diff --check`, and do not commit unless asked. Match LightGBM

performance without reproducible benchmarks.

Review the current `train_gpu.mojo`, expanded `histogram_gpu.mojo`, and
`test_gpu_training.mojo`. Complete and stabilize the end-to-end GPU path.

Requirements:

- Keep binned features and leaf assignments device-resident for the training
  session.
- Upload gradients and Hessians only once per boosting round.
- Perform row partitioning and child histogram construction on the GPU.
- Preserve sibling histogram subtraction.
- Support every objective that can correctly share the existing
  gradient/Hessian interface.
- Add explicit errors for unsupported combinations.
- Export the public GPU training API from the package.
- Add the GPU suite to the appropriate Pixi test task without breaking
  CPU-only CI.
- Add CPU/GPU model-quality, determinism, sample-weight, and edge-case tests.
- Benchmark complete CPU and GPU training, including setup and transfers.

Do not optimize specifically for Apple M4. Treat the existing
one-threadgroup-per-feature kernel as a portable correctness baseline.
